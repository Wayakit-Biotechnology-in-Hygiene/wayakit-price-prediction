## What it is

Wayakit project that suggests selling prices for the Saudi Arabia (KSA) products based on competitor prices. Today: Selenium scrapers (Amazon, Mumzworld, SACO and B2B stores; since F6, on the instance since 2026-11-24, Amazon KSA and Noon KSA through Apify and Selenium only for Mumzworld, SACO and the B2B stores) and Bedrock (DeepSeek V3.2, Haiku 4.5 fallback; since F2 on branch `f2-hardening`, Gemini before) to decide relevance → `scraper/competitors_complete.csv` → `ml_model/` (price per liter or per piece, p10–p90 trimming, RandomForest, per-SKU market band with a p75 ceiling since F7a) → `product.price.suggestion` in Odoo. It runs on the EC2 `wayakit-app-server` (eu-north-1, almost always stopped). Since the F3 cutover (2026-11-22): the schedule `price-intelligence/price-intelligence-monthly` starts it on the last Thursday of each month at 21:50 (CDMX), `pi-pipeline.service` runs `run_pipeline.sh` (one run, no stages) only inside the boot-guard window, and the `trap EXIT` stops it when it finishes; the old `default` weekly schedules are disabled (kept for rollback) and the old crontab lines were removed. The instance runs the **`server-improvement`** branch at a97b4b1 (F2 + F3 + F4 + F5 + F6 + F7a + F7b; pulled by hand on 2026-11-24, first from 0221cfc to 6d97e78 for F6 and then to a97b4b1 for F7a and F7b, no conda or bootstrap change; `pi-deploy.service` installed on 2026-11-22, no release pointer yet), not `main`, with the role `price-intelligence-instance`. Access through SSM (no SSH). November's monthly run was done by hand on 2026-11-24 with the upload in `--dry-run` (nothing written to Odoo; F8 review pending); the schedule `price-intelligence-monthly` is **disabled** so the 2026-11-26 run is skipped, and must be re-enabled afterwards (`python -m infra.schedule --enable`, dry-run first).

## Code map

- **`run_pipeline.sh`.** On the instance today (pre-F2): stage 1 and `--stage 2`. On `f3-infra`: **one run, no stages and no arguments** (Mafer, 2026-11-18): Odoo products → `scraper/analysis-odoo.csv` (keywords from the versioned `scraper/modifiers_mapping.csv`) → scraping (`timeout 30h`) → Odoo quotations and competitor products → ML (1a, 1b `--run_mode full`, 2, 3) → upload `--run_mode full`. Every step `|| exit 1`; any argument exits 1. The `trap EXIT` shuts the machine down and, on failure with `PI_ALERTS_TOPIC_ARN` set, sends an SNS alert with secrets redacted.
- **Scraper contract:** `__init__(driver_path, relevance_agent)` and `scrape(keyword, search_mode) -> list[dict]`, with `search_mode` in `{'volume', 'units'}` (exception: AeroSense does not receive `relevance_agent`; the Apify adapters also take an optional `client=` for tests and the smoke run, and read no secret in `__init__`). Each dict has `Product`, `Price_SAR` (full package), `Company` (the brand, never the seller), `URL`, `Unit of measurement` (`ml`, `L`, `fl oz`, `units`) and `Total quantity` (pack total, > 0); since F6 optionally `Seller` and `Origin` (the Apify adapters always return them; `build_row_data()` defaults them to `''` and `'unknown'`). Registered in `make_scrapers()` (`scraper/main.py`) and in `TARGET_MAP` (`scraper/config.py`; since F6, `noon` in Home, Automotive and Pets).
- **`competitors_complete.csv`** (`config.CSV_COLUMNS`): `date, industry, subindustry, type_of_product, generic_product_type, product, price_sar, company, source, url, unit_of_measurement, total_quantity, channel`, plus `seller, origin` since F6 (15 columns; the 13 original cells of Mumzworld, SACO, B2B and AeroSense rows are unchanged). Built in `build_row_data()` (`scraper/main.py`). The ML ignores `seller`; since F7b it carries `origin` (`1a_preprocess_data.py`; pre-F6 files and Odoo rows get `unknown`), and the Odoo competitor CSV carries the raw channel in `Source channel` (`retail` / `ecommerce` / `b2b`; `odoo_api_competitor_products.py` still folds retail and ecommerce into `Channel` B2C).
- **Apify (F6):** `scraper/services/apify_client.py` (stdlib REST client: token only in the `Authorization: Bearer` header, retries, polling, pagination, per-run caps and the process-wide USD 20 budget; `shared_client()` reads `APIFY_API_TOKEN` once, lazily, through `pi_secrets`; `preflight()`), `scraper/scrapers/apify_common.py` (the adapters' own size, count, pack and price parsing with parser bugs 1–4, 10, 11 fixed only here; currency; Wayakit exclusion; `derive_origin`; the shared "size gate → `filter_relevant` → wipes batch" step), `scraper/scrapers/amazon_apify.py` (`AmazonApifyScraper`, site `amazon`; the Selenium `amazon_scraper.py` is deleted) and `scraper/scrapers/noon_apify.py` (`NoonApifyScraper`, site `noon`). In `scraper/main.py`: the Apify preflight runs after the AI preflight (exit 1 on failure), `ApifyFatalError` (auth, other 4xx, `ApifyBudgetExceeded`) takes the same fatal path as `RelevanceAgentFatalError` (`ScrapingAborted`, exit 1, CSV untouched), `ApifyRunFailed` is a per-keyword error in the coverage report, and failed Apify keyword searches above `config.APIFY_MAX_FAILED_KEYWORD_RATE` (5 % of those attempted, strictly above) make the run exit 1 before replacing the CSV. Caps in `config.APIFY_*`.
- **Price per liter or per piece:** `ml_model/1a_preprocess_data.py` (`process_volumetric_data`, `process_unit_data`), not in the scraper. Since F7a it drops prices ≤ 0, quantities ≤ 0 and mass units (`g`, `kg`...), reads `litre`/`liter` as liters and flags multipacks from the scraper title (`is_multipack`, reusing `apify_common`'s pack readers).
- **Model** (`main()` in `ml_model/2_train_models.py`): two RandomForests (volumetric and units; 300 trees, `min_samples_leaf=1`, 80/20 holdout metrics in the log, `train_and_evaluate`) with `volume_liters` or `total_quantity` plus `type_of_product`, `subindustry`, `channel`, `generic_product_type`, `industry` and `company` (the brand on Amazon, Mumzworld and SACO). It no longer uses `approved_quote_price` as a feature (it is still the target for the Wayakit rows). It does not use the source. Since F7a (merged into `server-improvement` with PR #15 on 2026-11-24; on the instance since 2026-11-24, `server-improvement` @ a97b4b1): a repeated SKU joins its quotes once (bug 7), volumetric competitor rows of 5 mL or less are dropped, and the p10–p90 trimming only applies to types with 3 or more rows (bug 6: 2-row types were emptied). The market rows (`*_market_rows.joblib`) are the trimmed competitor rows without multipacks; no Wayakit prices. In prediction (`generate_predictions()` in `ml_model/3_predicted_prices.py`), with 3 or more market rows the price per unit is clipped to the SKU's band: at least the type's minimum (not for a volumetric size above the competitors' size range; packs of pieces get it at every size since 2026-11-25), at most the p75 of the similar-size rows (half to double the size; all rows when fewer than 3); a size above the whole market is capped at a smaller sibling SKU's price per unit; then the margin floor `cost × 1.30`, rounded up to the cent, always wins. **F7b** (merged into `server-improvement` with PR #17 on 2026-11-24; on the instance since 2026-11-24, @ a97b4b1; Mafer 2026-11-24, every B2C subindustry: Home, Automotive, Pets): for a B2C SKU whose type has 3 or more **Saudi reference prices** (`is_saudi_reference()` in `2_train_models.py`: an Odoo price with `Source channel` `retail`, a physical store in KSA, or a scraped row with `origin` `local`), the p75 ceiling comes from those rows only (`ceiling_source` `reference`); the floor and the model keep every row; B2B is unchanged. The upload skips products without a size. The log target and GroupKFold are left for a phase 2 (`docs/decisions.md`, 2026-11-24).
- **Odoo** (XML-RPC). Reads `product.master`, `sale.order.line` and `competitor.product`. Writes `product.price.suggestion` (`ml_model/odoo_api_price_suggestion.py`, `upload()`): since F2 it checks there is exactly one company, saves the current IDs to `odoo_previous_suggestion_ids.json` in the log folder (`PI_LOG_DIR`), `create`s the new batch and only then archives to `product.price.suggestion.history` and `unlink`s the saved IDs; any failure exits 1 and a failed cleanup is retried with `--cleanup-previous`. `--dry-run` writes the records to a CSV and reads no secrets. Sales come from the last 12 months (`sales_window()` in `ml_model/odoo_api_cotizations.py`). Importing the Odoo scripts has no side effects: each has `main(argv, session=None)`.
- **Relevance AI** (`scraper/services/ai_service.py`, `RelevanceAgent`) and **scraper main** (`scraper/main.py`): see "Relevance AI" below. `main.py` writes to `competitors_complete.tmp.csv` and renames it only on success, exits 1 on fatal errors, and always writes `scraper/coverage_report.csv` (found vs relevant per subindustry × type × site × keyword).

## Known pitfalls

- **Silent failures (fixed in F2, deployed 2026-11-22):** bare `exit()`, swallowed exceptions and stage 2 steps without `|| exit 1`. On the branch every error exits 1; do not reintroduce `exit()` or an `except` that only logs.
- **No `git pull` in the pipeline** since the 2026-11-22 deploy (the old stage 2 pull is gone). Until F4, code reaches the instance with a manual pull over SSM (the instance's `origin` now points at the organization repo URL): the GitHub repo is public, so anonymous HTTPS works; never put a personal account or token on the instance (if the repo is made private, a read-only deploy key generated on the instance).
- **Case-sensitive subindustry:** `TARGET_MAP.get` in `sites_for()` (`scraper/main.py`) uses `'Land Transportation'` and the data has `'Land transportation'`; those rows are never scraped and there is no warning.
- **New CSV column = `config.py` + `main.py` at the same time:** `csv.DictWriter` (`_run()` in `scraper/main.py`) uses the default `extrasaction='raise'`.
- **Odoo reads with 0 records exit 1** (F2): products, sales (rolling 12 months) and competitor products. An empty read would otherwise leave the previous run's CSV in use.
- **The Gemini key is in plain text** in `logs/cron.log` and `logs/pipeline_execution.log` on the instance (confirmed in F1; the old `ai_service.py` put it in the URL). Do not copy those logs anywhere or print them without redacting `key=`. Bedrock errors are logged with the model, exception class and AWS error code only (AWS messages can carry ARNs with the account ID).
- **One folder for logs and state, outside the code** (Mafer, 2026-11-18): `PI_LOG_DIR`, default `<repo>/../logs` (`/home/ec2-user/logs` on the instance). `log_config.py`, `run_pipeline.sh` (`pipeline_execution.log`; the pre-F3 `run_mode.txt` and `last_full_run.txt` are gone) and the upload's IDs file all use it, so F4 release folders never lose them. Never write logs or pipeline state files inside the code folder. Data files and reports (`scraper/coverage_report.csv`, `analysis-odoo.csv`, the ML CSVs and models) still live in the code folder; moving them out (S3 state) is F3–F4. Use an absolute path without `..` for `PI_LOG_DIR`.
- **A failing step does not stop the pipeline:** in the 13–15 Nov 2026 run, scraping hit the 30 h timeout with 53 rows and training and the Odoo upload in full mode still happened.
- **Inconsistent sizes in Apify:** in `junglee`, `Item Volume`, `Unit Count` and `Size` often do not match; the sizes are **conservative** (Mafer, 2026-11-23: a dropped row is better than a wrong volume; Wayakit sells liquids only, so solids are not wanted, and a kit of different products is not stored because it cannot be classified, while a multipack of the same product is kept with its total). **Ambiguous title → row dropped, on Amazon and Noon** (`apify_common.title_is_ambiguous`): a count of 2 or more ("28 oz, 4 Count"), a pack notation the parser does not read ("6/Carton", "Case of 6", "Multipack", "Duo"), a kit ("Kit", "Bundle", "Gift Set", "+ 3 Refills", "1+1" offers, a towel, cloth, sponge, mitt, pad, glove, bucket, wipes, chamois or microfiber after "with / and / & / + / , / - / w/ / incl." or before "Included", "2 Wash Mitts"; a brush or sprayer only with a count; a use clause such as "for Bedding and Towels" is not a kit), a dose, dilution or capacity ("1 oz per Gallon", "makes 5 L", "Treats up to 50 Gallons", "Capacity"), a yield ("Makes 8 Bottles"), "N Units", "2X 150 oz", a gallon container ("Bucket 5 Gallon"), or two sizes that are not the same thing said twice, including any word other than a pack or unit word between them ("500ml and 1L Refill", "Cleaner 250 ml, Conditioner 250 ml", "1L Blue, 1L Pink"; "24oz - 709ml", "4 L (1 Gallon)" and "3 x 500 ml (1.5 L)" are fine). A title that already shows its total ("400ml Twin Pack 2x200ml") is never multiplied again by its pack phrase. **A plain "oz" or a gallon in a title needs confirmation**: on Noon (title only, `title_volume(explicit_only=True)`) only ml, liters and fl oz count; on Amazon a plain oz must agree with a source that is not another plain oz, and the title-only size must be in ml, liters or fl oz (and, when the title states a pack, confirmed by an attribute). `amazon_apify.amazon_size` keeps the old Selenium rule "at least 2 sources agree" over {title, Item Volume, Size, Unit Count} (the old one used title, Volume and Item Volume; junglee has no Volume), else the title's size when no attribute contradicts it; a solid Item Form, an attribute multipack (Size "(Pack of N)", Unit Count "N Count") that the title does not state with the same number (Number of Items, often wrong, only blocks when the title's own size does not agree with an attribute), an aerosol or a can sized in oz ("1 17 ounce can" in Included Components), two attributes that agree with each other but not with the title's own size, or a ml result that another source states as the same number in fl oz without the title confirming it, gives no size; per-unit attributes never outvote a title that states a pack, and a ml attribute is read as fl oz only when the title states that number in fl oz. In the adapters (volume mode only) a plain "oz" / "Ounces" is fl oz unless it is a weight ("Net Wt", "(595 g)", or a text that names a solid or an aerosol: pods, powder, paste, bar, beads...), a gallon is 128 fl oz, fractions, case notation and "1.000 ml" ("1/2 Gallon", "12/19 oz") give no size, and volume-mode packs also read "Twin/Double/Triple Pack", "Pack of Six", "2 Units", "500ML*2"; weights never count. Units mode is unchanged. In the adapters a dimension ("40 x 40 cm") or a breakdown ("1.5 L (3 x 500 ml)") is never a pack multiplier.
- **Wayakit products show up in the results** (Amazon and Noon). Since F6 the Apify adapters drop them (brand, seller, manufacturer or title; Noon search items always carry `store_name`); before F6 nothing excluded them.
- **Append onto a pre-F6 CSV is refused** (since F6): `scraper/main.py --output_mode append` exits 1 if the existing file's header is not `config.CSV_COLUMNS`; use `overwrite` (the pipeline always does).

## `infra/` conventions (F3, applied 2026-11-18 and 2026-11-22; every re-apply still needs Mafer's OK)

- One script per resource, with boto3. Each one can be run more than once (if the resource exists, it updates it; it never duplicates it), accepts `--dry-run` and has a docstring in English that says what it leaves configured and how to use it.
- Shared configuration in `infra/config.py` (profile, region, tag, names, cron). Do not duplicate constants.
- `infra/` is a package: run scripts from the repo root as `python -m infra.<script>` (`--dry-run` first) and import with `from infra import config, _aws` (a bare `import config` collides with `scraper/config.py`). Read-only status: `python -m infra.check_pi`.
- Never applied from a test or a teammate: the lead runs each script against AWS only with Mafer's OK. Tests use `botocore.stub.Stubber` and fakes only.
- The new instance role is separate from `Wayakit-EC2-Secrets-Role` (rollback = associate the old profile again). Before switching, run the read-only CloudTrail audit `python -m infra.instance_role --audit-old-role`. The monthly schedule is created disabled; the old weekly schedules are disabled, not deleted. On the instance, `pi-pipeline.service` runs `run_pipeline.sh` only inside the boot-guard window (last Thursday, 21:40–23:00 Mexico City), so a manual start never runs the pipeline.
- Do not store the account ID or emails in the repo: the ID is obtained with STS and the email is passed as an argument.
- Do not name scripts after standard library modules (`secrets.py` broke boto3 in VdC).
- When adding a resource: new script + row in `docs/resources.md` + step in `docs/runbook.md` + decision in `docs/decisions.md` if applicable.

## Deployment — F4 (merged into `server-improvement`, instance bootstrapped 2026-11-22; `main` after the other tickets)

Until `main` receives `server-improvement` (deferred until the other tickets are done; Mafer, 2026-11-22), code reaches the instance with a manual pull over SSM; `pi-deploy.service` is already installed and does nothing while there is no release pointer. F4 (pull-on-boot): `.github/workflows/ci.yml` (a check) and `deploy.yml`, which after a green CI on a push to `main` runs `python -m infra.release deploy` with OIDC credentials (secret `PI_DEPLOY_ROLE_ARN`): it refuses inside the monthly window or if the instance is not stopped, publishes `releases/<sha>.tar.gz` + `.sha256`, moves `releases/current` (old value in `releases/previous`), writes `releases/deploy-request.json`, starts the instance and waits for `state/deploys/<request_id>.json`; on failure it moves the pointer back. On the instance, `pi-deploy.service` runs `/opt/price-intelligence/pi_deploy.py` on every boot before `pi-pipeline.service`: it installs the pointer's release in `/home/ec2-user/pi-releases/<sha>` and switches the `/home/ec2-user/wayakit-price-prediction` symlink atomically (never on failure), keeps 5 releases, and powers off only after a deploy-only boot outside the monthly window. A changed `environment.yml` is refused unless `pi_deploy.py --allow-env-update --sha <sha>` is run over SSM. Rollback: `workflow_dispatch` with a `sha` from `main`.
