# Reliability checklist

Checks that come from real incidents and from pitfalls already seen in PI. Not all of them are run: the reviewer reads the diff, looks for the **Trigger** that matches the files or patterns that changed and runs only those checks (usually 3 to 10). How to apply it: `verify` skill (`.claude/skills/verify/SKILL.md`).

Rules:

- **It is read from the base branch**, not from the change's branch, so a change cannot relax its own checks:
  ```bash
  git show "${PI_BASE_REF:-origin/server-improvement}":docs/reliability-checklist.md
  ```
  If it does not exist in the base yet (before this file is merged), the local copy is used and the `Verified:` trailer says so.
- Rows are **only appended** to the table. Changing or removing a check goes in a separate PR, with Mafer's OK.
- Each new incident adds a row: a trigger that can be read in a diff, a concrete check and an origin (date, incident or PR).
- Line references are from e25e2c9 (`server-improvement`, what runs in production).
- No check calls AWS, Odoo, Apify or Bedrock, and none runs `ml_model/odoo_api_price_suggestion.py`.
