# Checklist de confiabilidad

Chequeos que salen de incidentes reales y de trampas ya vistas en PI. No se corren todos: quien revisa lee el diff, busca qué **Disparador** coincide con los archivos o patrones que cambiaron y corre solo esos chequeos (normalmente de 3 a 10). Cómo aplicarlo: skill `verify` (`.claude/skills/verify/SKILL.md`).

Reglas:

- **Se lee desde la rama base**, no desde la rama del cambio, para que un cambio no pueda relajar sus propios chequeos:
  ```bash
  git show "${PI_BASE_REF:-origin/server-improvement}":docs/checklist-confiabilidad.md
  ```
  Si todavía no existe en la base (antes de integrar este archivo), se usa la copia local y se dice así en el trailer `Verificado:`.
- A la tabla **solo se agregan filas**. Cambiar o quitar un chequeo va en un PR aparte, con OK de Mafer.
- Cada incidente nuevo agrega una fila: disparador que se pueda leer en un diff, chequeo concreto y origen (fecha, incidente o PR).
- Las referencias a líneas son de e25e2c9 (`server-improvement`, lo que corre en producción).
- Ningún chequeo llama a AWS, Odoo, Apify ni Bedrock, y ninguno corre `ml_model/odoo_api_price_suggestion.py`.
